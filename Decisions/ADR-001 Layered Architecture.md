# ADR-001 Layered Architecture

## Контекст
Застосунок розробляється з допомогою агента; потрібна передбачувана структура, яку агент легко відтворює (задача T1 — каркас модуля) і яку легко перевірити рев'ю (T3).

## Рішення
Три шари: [[Routes Layer]] → [[Services Layer]] → [[Repositories Layer]]. Логіка рекомендацій — в окремому модулі [[Recommender]]. Залежності лише вниз; доступ до [[Database]] — тільки з репозиторіїв.

## Альтернативи
- Логіка прямо в обробниках Fastify — швидше на старті, але погано тестується й розмиває межі.
- Hexagonal / clean architecture — надлишково для проєкту такого розміру.

## Наслідки
- Сервіси тестуються без HTTP і з тестовою БД.
- Порушення шарів можна перевіряти автоматично (кандидат на [[Guardrail]] у ПР № 4).
